# InnocenceHarness Repository Guidelines

## Architecture

1. **Prefer plugins for reusable capabilities.** New providers, tools, skills, policies, message processors, and reusable domain capabilities should live in independently testable `packages/*` modules and register through the vendor kernel family and harness spine extension points. Pure presentation, host lifecycle code, and narrowly scoped changes inside an existing responsibility may remain in the host. Document any exception in the change summary.

2. **Keep the framework and capability layers separate.** The `vendor/kernel*` family is the framework layer. The `harness-*` packages are spine services that compose sessions and runtime capabilities. `plugin-*`, `tools-*`, and `provider-*` packages are capability plugins. Domain packages must remain host-agnostic and must not import or depend on Electron, React, React DOM, browser DOM APIs, `src/main`, `src/preload`, or `src/webview`; host framework dependencies belong only in root host code or explicitly named host adapter packages.

3. **Inject production sessions through the dynamic staging spine.** Production sessions must be created and wired by the dynamically staged spine rather than by presentation code or hard-coded host imports. Capability plugins load only from the two approved roots: packaged `resources/plugins` and the user's `~/.innocence/plugins` directory. Plugin loading, lifecycle, and disposal must remain explicit and testable.

4. **Integrate hosts and UI clients through ports, adapters, and slots.** Electron, a future CLI, tests, and UI clients must inject capabilities through typed interfaces, callbacks, configuration, factories, events, and slot registry contracts. UI client contributions use the `innocenceharness-plugin://` protocol and the slot registry. Domain packages must not call Electron IPC, `BrowserWindow`, React state, DOM presentation APIs, or CLI stdout directly.

5. **Keep core protocols host- and provider-neutral.** Canonical messages, deltas, tools, providers, skills, policies, permissions, and events must not contain Electron types, React components, IPC channel names, DOM objects, or provider wire payloads. Provider conversion belongs in `provider-*`; host conversion belongs in adapters; unavoidable cross-domain dependencies must be documented.

## Module Design

6. **Use divide-and-conquer and single responsibility.** Each module should have one clear reason to change. Treat roughly 250-300 lines in a production TS/TSX file as a signal to split by responsibility, such as `protocol`, `domain`, `adapter`, `store`, or `view`. Do not add unrelated behavior to already oversized modules such as `App.tsx`, `settings.ts`, or `sessions.ts` without first extracting the relevant responsibility.

7. **Keep presentation replaceable.** React components render typed view models and emit commands; they do not own Git, Playwright, attachment parsing, task state machines, or persistence rules. A feature must remain usable by a non-UI host unless it is inherently visual.

8. **Manage resources explicitly.** Plugins and runtimes that start processes, watchers, workers, transports, PTYs, browser contexts, or temporary worktrees must expose asynchronous cleanup and be disposed by their owner. Deleting a cache entry is not resource cleanup.

## Testing And Verification

9. **Require non-UI tests for domain behavior.** Every plugin or domain capability needs Node/Vitest coverage that does not start Electron or render React. Cover registration and the primary behavior with fake ports, fake runtime hooks, mock providers, or CLI-style `AgentSession` integration tests. UI tests supplement rather than replace these tests.

10. **Verify package and host boundaries.** New workspace packages belong under `packages/*` and need `package.json`, `tsconfig.json`, a `typecheck` script, and tests appropriate to their responsibility. Before completion run `npm test`, `npm run typecheck`, and `npm run typecheck:packages`. Also run `npm run package` when changing Electron main/preload code, packaging, native resources, workspace bundling, or embedded browser binaries.

## Editing Safety

11. **Preserve user work.** Never overwrite or revert unrelated working-tree changes. Task-level restore, review, and automation features must not use or mutate the user's Git index unless the user explicitly requests that operation.

12. **Use safe UTF-8 file operations.** On Windows, do not rewrite repository text with PowerShell `Get-Content`/`Set-Content`, CMD redirection, or other locale-dependent commands. Use repository-aware edit tools or Node APIs with explicit UTF-8 encoding.

13. **等待子代理、后台任务或异步工具结果时不设置超时时间。** 使用阻塞等待直到结果完成、明确失败或用户取消；不得通过短超时轮询制造假失败。

14. **Keep documentation out of Git.** Never add, stage, commit, or push documentation files. The `docs/`, `documentation/`, and `.superpowers/` directories are local-only and must remain ignored. The only documentation files permitted in Git are `AGENTS.md` and files named `README.md`; all other plans, specifications, reports, notes, and documentation artifacts are prohibited. `AGENTS.md` is the required repository-instruction exception.

## Expression

15. **Keep third-party names and trademarks out of development artifacts.** Code identifiers, comments, commit messages, changelogs, user-facing documentation, UI copy, and log output must not mention third-party product, company, or model names or trademarks; use neutral terms (for example "the plugin kernel", "the reference project") instead. Exemptions: dependency declarations and import specifiers required to resolve packages, opaque API key strings defined by external code, legal attribution files (`LICENSE`, `THIRD_PARTY_NOTICES.md`), and vendored third-party sources under `vendor/` (kept verbatim for upstream synchronization). Local, uncommitted working documents may reference upstream names when needed for development.

16. **Write all prompt content in English.** System prompt fragments, agent mode personas, subagent prompts, reminder/injection templates, and any other LLM-facing prompt text authored in this repository must be written in English, regardless of the UI locale or the user's language; conversational replies to the user still follow the user's language.

## Dependency Discipline

17. **Prefer installed components over hand-rolled code.** Before writing parsing, protocol, streaming, version-comparison, archive, transport, or crypto logic, first check the Node standard library and the workspace's already-installed dependencies, and reuse them so the hand-rolled surface shrinks instead of grows. When a dependency is added, land its first real consumer in the same change; a declared dependency with no import site is dead weight — remove it, or land the capability that justifies it. A well-chosen component replaces bespoke code (parsers, mappers, adapters) with a maintained, tested implementation; a dependency kept "for later" without a consumer does the opposite.

## UI Design System

The webview was rebuilt from scratch (2026-09) to mirror the reference AgentIDE interface: flat two-column shell, dark-first theme, compact tool rows. Rules below keep new work in that language.

18. **Token-first styling.** All colors, radii, shadows, and font stacks come from the semantic tokens in `src/webview/src/styles/app.css` `@theme` (`--color-background` / `--color-sidebar` / `--color-raised` / `--color-popup` / `--color-hover` / `--color-selected` / `--color-foreground(-strong)` / `--color-muted` / `--color-faint` / `--color-border` / `--color-hairline` / `--color-accent` / `--color-mode-accent` / `--color-diff-add` / `--color-diff-del` / `--color-tool-*`; `--radius-card` 16px for the composer card, `--radius-pop` 12px for every popup/floating surface) — never hardcode hex values in components. Dark is the primary theme, driven by the `.dark` class on `<html>` (no media query); the light mirror is the `:root` default and must stay functional in the same change. Fonts: UI sans (`--font-sans` system stack), code/paths `--font-mono`; interface text is one 14px baseline.

19. **Shell layout.** The page background is the sidebar gray (`--color-sidebar`); everything right of the sidebar is one black surface (`--color-background`) that floats over it with 12px left corners (top-left in the title bar's right segment, bottom-left in `<main>`), both corners removed when the sidebar collapses. The 265px sidebar is transparent over the page background (no border) and animates width 265↔0 (`--duration-fast` `--ease-smooth-out`, reduced-motion branch); when it collapses, the title bar's left segment switches to `--color-background` so the whole bar reads as one black strip. The 48px title bar (`app-drag`) reads left to right: sidebar toggle (a full-height 46px-wide flush-left button matching the `WindowControls` hit area, showing the app logo, hover `bg-(--color-hover)`, aria-label 折叠/展开侧边栏; the collapsed left segment is 120px = 46 toggle + 16 gap + 48 back/forward + 10 padding) + disabled back/forward stubs → conversation title (bold) → project pill (static label, no dropdown chevron, text centered; bound strictly to the session's own workspace — a session without one groups under 任务 in the sidebar and shows no project/branch pills, no fallback to the global workspace) → branch pill (GitBranch icon; null branch = hidden; interactive `BranchPicker` popover — search, local branch list with the current branch checked plus its uncommitted-changes count, create-and-checkout, disabled Git graph stub; checkout goes through the `workspace:git-checkout` IPC) → "…" session menu (pin/rename/archive/mark-unread, file-manager/copy-path/log-path/session-ID entries via the `host:reveal-path` / `host:open-external` / `session:paths` IPCs, settings, disabled trace stub, feedback link; unavailable entries stay disabled with an aria-description reason) → right cluster (external-editor chip → app-menu chevron `AppMenu` (46px full-height trigger left of the window controls; dropdown: new task Ctrl+N / open workspace Ctrl+O — both mirrored as AppShell global shortcuts — reveal workspace via `host:reveal-path`, about dialog, process-monitor dialog polling `app:metrics`, feedback link, export logs via `app:export-logs` directory-pick copy, close window; no-capability entries like check-updates/community/docs stay disabled with an aria-description reason) → `WindowControls` over the `window:*` IPC channels — 46px hit areas, close hover `#e81123`; macOS renders nothing). The landing state leaves the title bar middle empty. Changing the page gray requires syncing `src/main/appWindow.ts` `backgroundColor` and the `index.html` startup background in the same change. The floating `GitCapsule` (319px, top/right 18px) squeezes the chat column left by reserving a 337px right gutter only when it has visible content (rule 20) and the conversation container is ≥1280px (`capsuleRightGutter` in `components/chat/chatLayout.ts`, aligned with the reference container-query breakpoint); below that breakpoint there is no squeeze, the capsule auto-collapses to a compact "更改 +N −M" chip (or icon), and it auto-expands again when crossing back — manual toggles hold while the threshold side is unchanged. The timeline keeps 56px top clearance (`pt-14`) so the floating capsule/chip never covers the first rows.

20. **Landing + chat surface.** Landing: faint watermark logo (CSS-mask silhouette of the root `logo.svg` in the foreground color at 0.06 — theme-adaptive in both dark and light), time-of-day greeting (`greetingKeyForHour` + `chat.greeting.*` keys), centered composer card (max 720px) with a project/branch header row, and quick-action chips that only fill the composer draft (never auto-send). Chat: headerless assistant frames with `.msg-body` rhythm (14px, line-height 1.7, 32px gaps via `space-y-8`); user messages are right-aligned rounded bubbles (12px with a 3px tail corner); compact `ToolRow` lines (icon + verb + mono title + path + ±diff counts, `.tool-sweep` while running; on edit/write/read rows the file cluster — icon + name + path + ±counts — opens a dock `file` tab showing that call's change or the original text via `onOpenFile`, while the trailing chevron button and the verb area toggle the inline details accordion; the expanded diff block is capped at `max-h-60` with its own scroll so long writes never stretch the timeline); thinking renders as a ghost row (`chat.thinking.*`). When the last turn was interrupted (assistant message without completion metadata), that message row carries a 「继续」 icon button (RotateCcw) that re-sends the continue prompt; every user bubble shows a hover copy button and the latest user message additionally an edit-and-resend pencil (inline textarea with an ArrowUp confirm icon button and an X cancel button; Enter or confirm REPLACES the edited message — `chat:resend` truncates the store + rewritten transcript and rewinds the route runtime history before the new turn, refused on running or task-bound sessions — while Esc or cancel reverts; resend failure reloads the store and toasts `chat.error.resendFailed`). Sending any message re-pins the timeline to the bottom. The sidebar keeps no persistent filter input — the filter icon opens a popover with view (按项目/时间线) and sort (更新时间/创建时间) sections, the header tools row also carries a collapse-all toggle (Shrink/Expand, collapses every section of the current view, re-click expands) and the archive icon switches the whole content area to an archived list (two-line rows: title + relative time over project name + always-visible restore/delete) instead of appending a section; the collapse-all toggle and the filter popover render only in the projects view (the groups view keeps just the `#` create button and archive); the by-project tree wraps its sections under two collapsible top-level groups, 项目 and 任务 (`SidebarProjectTree`; session rows live in `components/SessionRow.tsx`; a session row swaps the relative time for in-flow hover action buttons (no absolute positioning — the buttons take the time's slot so text never slides under them), marquee-scrolls an overlong title on hover (`.marquee-title`, distance/duration from measured overflow), and after a 350ms hover dwell pops a pointer-events-none preview card at the row's right edge (last user + assistant text via `messages:list`, portal-fixed, `.rise-in`)) — each group header row shows a hover-revealed drag grip (HTML5 drag reorders the groups up/down — dragged row goes translucent, an accent `.drop-indicator` line marks the before/after insertion edge, and the moved group replays a `.drop-settle` animation; local state only) and a hover-revealed 「+」 (项目组 = 新建项目 via the workspace directory pick, 任务组 = 新建会话), the 任务 group renders no-project sessions directly while the 项目 group nests the project sections; each project header row has a hover-revealed action trio (… menu with 在资源管理器中打开/复制路径 via `host:reveal-path`, 浏览文件, 新建任务 — hidden for the 任务 no-project group). 浏览文件 swaps the sidebar content into `FileExplorer` mode (返回任务 back row, substring search over `workspace:list-files`, lazy directory tree via `workspace:list-dir`, orange change dots fed by `workspace:git-review-files`, file clicks open a dock `file` tab with content from `workspace:read-file`). The 分组 view (`components/sidebar/GroupsView.tsx`) lists persisted groups as sections — colored `#` icon from the group's color id (seven `--color-group-*` tokens), name, no count, hover-revealed ⊕ new-session-in-group (eagerly creates the session and moves it in) plus a delete-group button (members fall back to ungrouped, sessions are never deleted), collapse chevrons, and an empty group's dashed 「新建任务，或拖拽到这里。」 hint (click = same as ⊕) — followed by the ungrouped sessions flat without a header; the header-tools `#` button (groups view only) opens the create popover (name input defaulting to New Group + seven-color picker); rows inside a group carry hover actions 移动到顶部/移出分组, and every row is HTML5-draggable into a group section or the ungrouped zone (`sidebar:move` / `sidebar:reorder`; group color persists through `sidebar:group-upsert`). The timeline also carries a left-edge `ChatDashes` ladder, a floating back-to-bottom button, and the floating `GitCapsule` (319px, top/right 18px, `--radius-pop`). The capsule is hidden by default and appears only when at least one condition holds (`capsuleHasContent` in `components/chat/chatLayout.ts`): the project is a Git repo (`isGitRepo` = branch detected or changes statable), a todo checklist exists, subagents have been invoked, or live terminals exist — sections render per condition (Git rows 更改/分支/提交或推送, collapsible 进程 checklist fed by the latest todo tool call, 智能体 summary row with running/已结束 status and count, 终端 summary row with count); clicking the 智能体/终端 row opens the corresponding live view (dock subagents tab with the latest live run selected, or the bottom terminal panel / dock terminal tab). The scroll region keeps direction-aware bottom pinning (user scroll-up unpins, <48px from bottom re-pins; streaming pins instantly); pinning uses `scrollTo(scrollHeight)` directly (an anchor div inside the `pb-8` column once stopped `scrollIntoView` 32px short), and a `ResizeObserver` on the timeline column re-pins while pinned so height growth that does not change the `messages` reference (async code highlighting, waiting-row mount/unmount) still follows to the true bottom.

21. **Composer.** One card (`--radius-card`, `--color-raised`) for both landing and follow-up modes; toolbar order: "+" context menu (attachment item stays disabled with an aria-description reason; @ and / items insert the prefix into the textarea) → permission picker (four modes in the order 变更前确认/自动编辑/计划模式/完全访问; the full tier renders in `--color-mode-accent` orange) → agent-mode picker (`AgentModePicker`, same popover style with a max-height scroll cap; each row shows a title plus a description line — built-in mode ids resolve through the `agentMode.<id>[.desc]` i18n keys via `dictHas`, user-installed modes fall back to the catalog's raw title/description; catalog from the `agents:modes` IPC via `useAgentModes`, always containing `default`; selection writes `settings.activeAgentMode`) → right side: two-level model dropdown (provider column → model submenu, `管理模型` entry routes to settings/models), thinking-effort picker (three levels 低/高/最高 mapped to low/high/max; legacy values display their label but are not listed), and the inverted square send/stop button. The streaming spinner no longer lives here — streaming renders a `WaitingRow` (spinner + rotating `chat.waiting.*` patience hints) at the bottom of the timeline instead. Quick prompts and any LLM-facing strings follow rule 16 (English).

22. **Icons, motion, chrome, tests.** UI icons are `lucide-react` at stroke width ~1.3–1.5; no remote icon URLs (CSP `img-src 'self' data:`); the app logo resolves via the root `logo.svg` import. Motion runs on the token scale declared in `app.css` `:root` (`--duration-*` / `--ease-*` / `--distance-*` / `--scale-*` / `--blur-*`) — animations and transitions reference these tokens, never hardcoded `ms` or `cubic-bezier` values. Shared animations live in `app.css` (`.dropdown-in` `[data-state]` open/close, `.modal-in`, `.toast-in`, `.rise-in`, `.stagger-in` with per-item `--i`, `.acc-panel` grid-rows accordion + `.acc-panel-inner`, `.text-swap`, `.icon-swap`, `.animated-gradient-text` shimmer, `.tool-sweep`, `.stream-caret`, `.drop-settle`) — every new animation adds a `prefers-reduced-motion: reduce` branch in the same change. Clickable controls default to `cursor: pointer` via a zero-specificity `:where(button, summary, select, a[href], [role="button"], [role="menuitem"], [role="switch"], [role="tab"])` rule in `app.css` (drag grips use `cursor-grab`/`active:cursor-grabbing`); explicit `cursor-*` utilities still override it. The chat surface has exactly one `<main>` element (the AppShell column); sub-surfaces render `<div>`/`<section>`. UI behavior is covered by jsdom Vitest tests next to the components plus pure-module tests (`state/chatStream.ts`, `state/sidebarTree.ts`, `components/chat/toolRows.ts`); keep the `data-testid` contracts (`full-sidebar`, `chat-timeline`, `chat-composer`) stable.
